# Phase 1 audio soak — 2026-10-20

## Method

- Harness: `tools/KyappuTone.Soak` (Release), driven by `scripts/soak-audio.ps1`.
- Source material: three generated 60 s stereo WAVs (220/330/440 Hz fundamentals), gaplessly crossfaded with a 2 s overlap.
- Signal path: FFmpeg decode → mix → crossfade → ten-band EQ (Rock preset, −3 dB preamp) → limiter → WASAPI shared-mode output (10 ms).
- Planned phases: 7.5 minutes EQ only, then 7.5 minutes EQ plus a simulated 60 Hz visualizer mapping loop (64 log-spaced bars).
- Sampling: every 30 s, CPU as percent of one core (`TotalProcessorTime` delta / wall delta), working set, managed heap, rendered audio seconds, render callbacks, unexpected device stops.
- Pass criteria: no unexpected device stops, render callbacks > 0, rendered-audio / wall-clock ratio ≥ 0.5.

`realtime_ratio` is rendered audio seconds divided by wall-clock seconds; 1.001 means the engine kept up with real time and produced no silent-starve gap large enough to change the ratio.

## Live-device check

`WasapiOutputTests.WasapiDevice_Plays_A_Real_File_When_A_Device_Is_Available` opened the default endpoint, played the generated 1 s file, and observed the clock advance past 400 ms in 526 ms. This confirms the shared-mode path on this machine; it is not a soak.

## Limitations

- The harness measures the audio engine and DSP chain, not the packaged UI, tray, SMTC, taskbar overlay, or the on-screen SwapChainPanel visualizer.
- The 1 h criterion in the spec is unverified.
- The 15-minute tone run was cancelled by user request; no crash event scan was completed.
